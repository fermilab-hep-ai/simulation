# Simulation for Level-1 Trigger Foundation Model

## Usage

### Setup 1st step
To use the package, first run:
```bash
git clone -b jsc_compatible https://github.com/fermilab-hep-ai/simulation.git
cd simulation
```

### Setup 2nd step
Then, download the MinBias events:
```bash
wget https://cernbox.cern.ch/remote.php/dav/public-files/IyG0C0tfkXW7ifF/MinBias_100k.pileup
```

### Setup 3rd step
Build the docker image locally using /docker/Dockerfile or use a remote source (to be specified).
Run
```bash
apptainer build container.sif docker_image
```
to build the Apptainer image, where docker_image is the remote source of the docker image, or, in case it is saved locally as a .tar file, docker-archive:filename.tar .

### Running a single sample generation locally without Slurm (not recommended on Cluster login node!)
Run the `run.sh` command with the Apptainer image
```bash
apptainer exec --bind $simdir container.sif $simdir/run.sh $process $nevents $seed $simdir $outdir $istest $label
```
The script will create create a tmpdir inside outdir, where it stores the temporary files. The resulting root file, parquet file and validation plots (if $istest is True) are stored in a folder $process-$nevents-$seed in outdir.

## Submitting sample generation to Slurm
Make sure that you followed step 1, 2 and 3 of the setup, then use `submit_to_slurm.py`:
```bash
submit_to_slurm.py [-h] -o OUTDIR [-n NEVENTS] [-p PROCESS] [-s SEED] [--simdir SIMDIR] [-csv CSV] [-t] [-l LABEL] [-hp]
```
Any adaptations to a different cluster and with different account or parallelization settings have to be done inside the respective functions in submit_to_slurm.py.

To efficiently submit multiple jobs, run:

```bash
write_jobs.py [-h] [-n NEVENT_PER_JOB] [-i SEED_INCREMENT]
```
to create a csv file containing all job specification, or write a csv files with all desired jobs yourself using the same layout. Then use `-csv` option with the csv file containing the jobs.

Use high_parallel (`-hp`) mode to double the amount of jobs per node (this might run into timeout, depending on the complexity of the jobs). 

Use `-o` flag to specify the location where you have a lot of free space to store the output root file, parquet file and validation plots (if -t is given).

Use `-p` flag to specify the name of the process you want to run from the available ones, if you don't use a csv file. If you don't specify any, the `'WJetsToLNu_13TeV-madgraphMLM-pythia8'` will be generated by default.

Use `-n` flag to specify number of events to be generated (1k by default), if you don't use a csv file.

Use `-s` flag to specify the random seed of the event generation (0 by default), if you don't use a csv file.

Use `-t` flag to indicate that the job should be in testing mode, which will write timing results and validation plots.

Use `-l` as a label for the slurm job submitted to the cluster, default is 'test'.

Use `--simdir` flag to specify the location of the `simulation` folder that will be used by slurm to pick up the cards and processes details, takes current folder as default. Not necessary if calling submit_to_slurm.py from the simulation folder.

The log files will be written to `logs/` in the folder `$proccess-$nevents-$seed`.

### Checking job status

To check the status of your slurm jobs use
```bash
squeue -u $USERNAME
```

If for whatever reason you would like to remove submitted jobs, use
```bash
scancel $jobID
```
(the `jobID` can be found out by running the `squeue -u $USERNAME` command)
